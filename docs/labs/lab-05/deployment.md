## 1. Stack and changes from the reference

The reference is the Lab 5 Starter Kit (TokTickIT: Node.js, React, PostgreSQL, Prisma, one container,
Cloud Run, Cloud SQL, Secret Manager, Artifact Registry, GitHub Actions). This repository uses the
same reference stack. Its own differences:

| Area | Reference (kit) | This repository | Why |
|---|---|---|---|
| Prisma location | `server/prisma`, Prisma 5 | `prisma/`, `prisma.config.ts` and the generated client `generated/prisma` at the repo root; Prisma 7 with `@prisma/adapter-pg` | Layout from Labs 1–4 |
| Server build | `npm run build` → `node dist/index.js` | No build step; the server runs TypeScript through `tsx` | Layout from Labs 1–4 |
| Attachments | Bytes in the database | Since Lab 5: bytes in table `AttachmentContent` (one row per attachment, `ON DELETE CASCADE`), kept out of ordinary attachment queries | Labs 2–4 wrote files to `uploads/`, which Cloud Run loses on every deploy (R-04) |
| Sessions | Session stored in the database | Signed JWT in the `toktickit_session` httpOnly cookie, 8-hour lifetime | Stateless: nothing lives in server memory, so a session survives a restart, a redeploy and a second instance as long as every instance shares the same `JWT_SECRET` (kept in Secret Manager). Trade-off: sign-out clears the cookie but cannot revoke a token before it expires |
| Extra secret | Database URL, admin and demo passwords | Also `JWT_SECRET` | The server refuses to sign sessions without it |
| Smoke-test sign-in | Login response `token` + `Authorization: Bearer` | Cookie-based session | *(Issue 7: adapt `deploy/smoke_test.py` or leave the optional login check off)* |

## 2. Environment variables

Every setting is read from the environment (R-02). `.env.example` lists them all with placeholder
values; copy it to `.env` for local runs and never commit `.env`. On Cloud Run, secrets come from
Secret Manager and plain values from the service configuration.

| Variable | Used by | Purpose | Secret? | Local value | Cloud Run value |
|---|---|---|---|---|---|
| `DATABASE_URL` | server, migrate/seed | PostgreSQL connection string | **Yes** | `.env` (docker-compose database) | Secret Manager `toktickit-database-url` (Cloud SQL socket `/cloudsql/<connection name>`) |
| `JWT_SECRET` | server | Signs session tokens | **Yes** | `.env` (`dev-only-change-me`) | Secret Manager `toktickit-jwt-secret` *(created in Issue 4/5)* |
| `NODE_ENV` | server, seed | `production` turns on secure cookies, SPA serving and the production seed rules | No | `development` | `production` (env var) |
| `PORT` | server | Listening port | No | `3000` | Set by Cloud Run (`3000`, matching the image) |
| `CLIENT_URL` | server | Allowed CORS origin for the separate Vite dev server | No | `http://localhost:5173` | Not needed (same origin) |
| `ADMIN_PASSWORD` | seed | First administrator's password (`john.smith@toktickit.com`, must change at first sign-in) | **Yes** | Unset → local default | Secret Manager `toktickit-admin-password`, generated by `deploy/deploy.sh`; **required** in production |
| `SEED_DEMO_DATA` | seed | Load demo users, tickets, comments and Actions Taken | No | Unset → `true` | `false` unless deployed with `--demo` for Lab 6 UAT |
| `DEMO_USER_PASSWORD` | seed | Password of every demo user (must change at first sign-in) | **Yes** | Unset → local default | Secret Manager `toktickit-demo-password`; required when `SEED_DEMO_DATA=true` |
| `CLIENT_DIST_DIR` | server | Folder of the built SPA served in production | No | Not used | Optional; defaults to `<repo>/client/dist` |
| `VITE_API_URL` | client (build time) | API base URL baked into the bundle | No | `http://localhost:3000` (unset gives the same) | `""` — same-origin calls to `/api/...` |

The seed validates `ADMIN_PASSWORD` and `DEMO_USER_PASSWORD` against the password rules (BR-07) and
never prints them. Its error messages name the variable, never the value. The local default
`InitialPassword123!` (docs/lab-03/specification.md §7.2) applies only when `NODE_ENV` is not
`production`.

## 3. Commands

### Local (no Docker for the app)

```bash
docker compose up -d db                 # PostgreSQL only
npm ci && (cd server && npm ci) && (cd client && npm ci)
npx prisma migrate deploy               # apply migrations (repo root)
npx prisma db seed                      # idempotent seed (repo root)
(cd server && npm run dev)              # API on http://localhost:3000
(cd client && npm run dev)              # UI on http://localhost:5173
```

### Tests

```bash
(cd server && npx vitest run)           # API, unit and migration tests (needs the database)
(cd client && npx vitest run)           # component tests
npx playwright test                     # E2E (starts both dev servers)
```

On Windows, run the client tests from a path with an uppercase drive letter (`C:\...`). From a
lowercase `c:\...` working directory, Vitest loads two copies of its runner and every suite fails
with `Cannot read properties of undefined (reading 'config')`.

### Production mode locally (what the image will run)

```bash
(cd client && VITE_API_URL= npm run build)
(cd server && NODE_ENV=production npx tsx src/index.ts)   # UI and API on http://localhost:3000
```

## 6. Release procedure *(Issue 7)*

Planned flow (R-07, R-08): feature branch → Pull Request into `lab5-staging` (CI `test-and-docker`
plus a teammate review) → release Pull Request `lab5-staging` → `main` → **Deploy demo** builds the image
tagged with the full commit SHA, runs the migration job, deploys by digest and smoke-tests the URL.
How to find the running commit, how to roll back with `image_tag`, and the pause and teardown steps
are added once the pipeline runs.
